# Add an engine

1. Record specifications, source IDs, confidence, conflicts and gaps in [research](research/README.md). Building does not fill gaps from memory or perform new research. A builder-required gap needs an explicit documented design decision.
2. Create `src/engines/<id>/index.js` with the keys in `REQUIRED_KEYS` from `src/engines/schema.js`. Keep identity/layout/geometry/valvetrain/features/ratings/curves/turbo/telemetry/startSequence/audio/inspect/walk/dyno/look/explode/oil/ui/provenance together. Supply `copy: () => import('./copy.js')`. Use independent data; a family must consume the supplied entry rather than import a default engine.
3. Record provenance for every numeric value. A subtree `design` record covers illustrative values; sourced/derived/conflicted values cite the research source IDs and explain limitations. Validate with `validateEntry(entry)` in a Node test. Unknowns stay explicit; never silently substitute a value that makes the builder appear valid.
4. Match the family contract. The current V8 OHV family retains a literal crank throw for a 99 mm stroke, so a different-stroke engine requires a separately reviewed family change. Test firing order/intervals, TDC/stroke, valve timing, finite kinematics, rated peaks, telemetry, audio cadence and walk clearance.
5. Create a lazy copy module exporting `COMPONENT_CARDS`, `pistonCard`, `rodCard` and `engineSummary`. Cover every family part ID and selectable stand/cell card. Keep unresearched construction illustrative and disputed claims qualified. Never copy engine-specific names or unsupported differences from another entry.
6. Register the ID and lazy loader in `src/engines/index.js` only after schema/provenance/copy pass. The UI/picker reads registry data; labels, default calibration, presets and scales belong in the entry. Keep the synthetic fixture restricted to Vite test mode.
7. Add a browser module under `tests/browser/` using the runner's `{page, open}` interface. Verify URL loading, actual canvas branding, model parts, start/preset/calibration behavior, switching/rollback, view preservation and resource counts. `window.__ENGINE__` is the sole QA hook; QA rendering advances fixed simulation steps explicitly.
8. Run `npm test`, `npm run check`, `npm run build`, `npm run check:dist`, `npm run test:browser`, and the documented baseline comparison. Verify each real entry is lazy-loaded in its own production chunk and the fixture is absent. Baselines are only re-captured in an expressly authorized, logged package; never weaken assertions or comparison guards.
9. Append decisions, source limitations, changed-file hashes and actual verification output to [build-log.md](build-log.md), then update [handoff.md](handoff.md). Keep manual/Windows/audio/FPS evidence separate from headless software-rendering checks. Follow the human's current approval scope for the next package and any Git/publication action.
