## Inspection and decisions

- `src/environment.js` no longer exists: the real export is in `src/environment/cell.js`. The existing stand builder requires cell-owned helper functions, registers into the cell's map, and its badge is updated by the cell. Separate these ownership dependencies.
- No direct `Math.random` occurs in stand.js, but Three.js constructors call `generateUUID`, which consumes Math.random. Simply moving stand allocation past the remaining cell construction shifts the seeded dust stream. Preserve the allocation point using an optional caller-supplied attachment callback at the old stand location. The cell must neither import nor invoke buildStand itself; main owns that call and the stand result. Keep the normal synchronous cell return value.
- Do not add an extra Three.js parent group: retain the existing two stand/dyno nodes under the supplied attachment parent, with the same order and world transforms. Return both roots as owned nodes. This avoids extra UUID draws and keeps root traversal/order unchanged.
- Move the stand-only iBeam helper and stand helper/material setup into stand.js. The cell retains its own addGroup helper for room props. Set stand/dyno dynamic flags before the cell's static merge, then call the stand's explicit finalize method from main after the cell completes. This preserves the old root/stand/dyno merge order and UUID consumption. finalize should be safe to call only once (subsequent calls no-op).
- The cell owns cell branding and gauges; the stand owns its badge and setBranding. Require a valid entry for redline reads, removing the documented fallback-to-1 gauge issue without changing valid-entry values.
- Move the existing centerRadius/dynoBox into the stand's collision result unchanged. Also return guardBox derived from the existing guard geometry/world transform, without inventing new dimensions. Main combines cell and stand collision data when calling the unchanged walk-world builder. That legacy builder continues using its original dynoBox behavior; consuming guardBox is a later collision integration task, not an unlogged solver change.
